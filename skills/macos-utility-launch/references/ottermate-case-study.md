# OtterMate 案例：哪些结论可以复用

本案例来自水獭助手的实际开发与验证，记录截至 2026-11-01。项目公开入口：[Vtous/OtterMate](https://github.com/Vtous/OtterMate)。不包含用户本机路径、个人规则或原始测试日志。

## 问题与实现

用户希望进入不同应用时自动选择合适的输入法，方便使用已有语音输入法。最终采用原生菜单栏工具，监听应用激活并通过系统输入源 API 选择已启用的输入法，不录音、不处理语音识别。

实现包含按应用规则、可选默认值、停用规则豁免、暂停恢复、规则搜索、导入导出与备份、可选登录启动。进入应用后允许用户手动切换，不持续锁定输入源。

## 验证与边界

22 项核心自动检查覆盖规则及配置逻辑；用户配合两个空白应用分别选择 ABC 与中文输入法，实测切换、暂停恢复、激活后手动更改及 App 退出重开后规则保留。

验证环境为一台 Apple Silicon Mac，macOS 27.2；安装包目标为 arm64，最低构建目标 macOS 14。未完成全面跨机/跨系统验证，也未完成整机重启后的登录启动测试。登录项的存在、指向与开启状态有界面核对。

## 品牌与图标

早期名“随用输入”，最终用户确定中文“水獭助手”、英文“OtterMate”。App 图标经历键盘、水獭、圆头修正、替换为白键盘、删除难辨认的尾巴等迭代。菜单栏独立使用简化水獭头像，透明模板适配深浅外观。

经验是保留已批准部分，每次按反馈局部修改；菜单栏不直接缩小整张 App 图标。

## 两类图标故障

启动器显示旧图时，只刷新应用登记未立即解决；资源独立命名、构建号与针对应用登记的处理后，用户确认新图显示正常。

登录项小图出现乱码时，大尺寸图正常。最终用官方 `iconutil` 生成完整标准/Retina 表示并反向检查，登录项与后台活动中的小图恢复。不能把所有图标问题都归因于缓存。

## 改名与分发

更新展示名称并保留内部 bundle identifier 和配置目录，核对用户原规则没有变化。登录项引用得到保留；这次具体安装处理不能直接作为所有应用的通用升级器。

公开版单独整理源码和双语资料，排除日常规则、测试记录及备份。源码放 Repositories，安装 ZIP 与校验和放 Releases，并核对远端文件内容与安装包 digest。

发行采用 ad-hoc 签名，未使用 Apple Developer ID 或完成公证。订阅收费仅有讨论，没有开发支付或授权服务。后续如开展这两项工作，需要新的实现与验证。
